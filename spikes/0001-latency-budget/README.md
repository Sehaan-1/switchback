# Spike: does the engine's hot path make #2 a latency decision?

One file, `hotpath.py`. It prices a routing decision — constraint filter, one Beta draw
per candidate arm, argmax, propensity record — plus the outcome-ingest path, the live
heap of the posterior store, and the GC regime in which a garbage collector could
plausibly threaten a 2 ms p99 budget.

```bash
python3 hotpath.py                 # ~25s on a 2-core box
python3 hotpath.py > /dev/null     # RESULTS.md is the committed output
```

## Why this measures Python

Deliberately, and it is not a proxy for "Go is slow." There is no Rust or Go toolchain in
the environment this was written in, and the question asked by #2 is not "which of the two
is 3× faster on a loop" — it is "**does either of them matter**." CPython is the pessimistic
instrument: 1–2 orders of magnitude slower than native code for interpreter-dominated
numeric work. If a decision fits its latency budget while *interpreted*, the language and
the collector are not the bottleneck, and the premise of the ticket's first consideration
dissolves. The verdict line is therefore printed at a 1.0× extrapolation factor, i.e. under
the assumption that native code buys us nothing at all.

The results that actually bind are structural rather than timed:

- cost is O(candidate arms), not O(arm space) — the arm space sizes memory, not latency;
- 184k arms × 24 B with no pointers = 4.4 MB of live heap the GC can bulk-skip;
- GC cycle frequency depends only on allocation rate and live heap, so 0 alloc/decision
  removes the collector from the latency story regardless of which language is chosen;
- every neighbouring component (acquirer HTTPS ~350 ms, 3DS ~8 s, a loopback sidecar call
  ~170 µs) is 1–3 orders of magnitude larger than the engine's own compute.

## Not in scope here

`RESULTS.md` is generated output — regenerate it, do not edit it. `B1`/`B2` are analytic
models with their constants inlined and labelled, not measurements; if a constant changes,
say so in the PR. Real Go benchmark numbers for `Decide()` are #17's job, in
`go test -bench`, regenerated by script and committed — this directory is the format
that ticket should inherit, not the artifact it should match.

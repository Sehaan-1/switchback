[F6] precedence properties
     permuting the merchant's precedence order: eligible set identical on 100.00% of 20,000 decisions
       precedence decides which rule is WAIVED when nothing is legal; it never
       decides what is legal, so it cannot be used to reorder policy by mood
     waive-vs-re-scope on the domestic rule, EEA traffic. Residency AND the
     margin floor are waived in every row, so the only variable is the domestic
     rule itself:
       as shipped (card_country) :  0.52 arms/decision
       waive the rule entirely   :  4.51 arms/decision
       re-scope  (card_region)   :  3.52 arms/decision
     -> three different worlds from one rule, and the middle one is the point:
        waiving recovers all 4.00 arms the domestic rule was holding
        back but stops constraining anything; re-scoping recovers 3.00 of
        them and keeps a checkable regional guarantee. A ladder that can only
        waive has no middle rung, and an audit log that records 'relaxed'
        without saying WHICH of the two happened cannot tell them apart after
        the fact.
     the UK case, where 'region' stops meaning one thing:
       as shipped (card_country)     0.00 arms/decision
       waived                        1.00 arms/decision
       re-scoped (card_region)       0.00 arms/decision
       expressed as a region LIST    1.00 arms/decision
     -> for a UK card, neither 'same country' nor 'same geographic region' is
        satisfiable: no acquirer is domiciled in GB, and 'UK' is not an acquirer
        region in the catalog, so both readings of 'domestic' leave the set
        empty. What the merchant actually means is a REGULATORY region, which
        `acquirer_regions` expresses with the same shape and the same catalog
        field the residency rule reads. Same rule head, same audit story, one
        param - which is why the schema grew that param instead of the ladder
        growing a waiver the compliance team never signed.

## Decision

1. **The "cost-only baseline" is ADR-0002's R25 procedure closed over three named implementations, and the headline measurement contradicts the spec's sign — so the headline is the measured pair, not the promised sign.** R25 says: swept cost-only frontier; equal effective cost means matched on **cost per authorized transaction** (cents per auth, `Σ fees ÷ auths`), never per request. The frontier here is degenerate in the useful direction: it collapses to a point — the optimum under `Σ c̄(s)·1[ŵ(s) ≥ q]` with no risk learning is the minimum-MDR processor under MDR-tiebreak (`mdr_only` router); the two money-bearing infrastructure routers complete the panel: `cost_aware_loaded` (minimize fully-loaded cost per attempt = quoted MDR + fixed fee + attempt fee) and `ev_table_static` (maximize `θ̂·(MDR+win) − fully-loaded cost` with θ̂ from a 2,000-transaction uniform calibration prefix never re-learned in the window). All three route everything, depth 2, through the identical execution loop. The measurement under the counter-coupling protocol (ADR-0005), three scenarios × n=60,000: **the learned TS policy authorizes 16.1–17.0 pts fewer than the MDR-only endpoint and 19.1–20.7 pts fewer than the strongest calibrated static on every scenario, and its realized margin is ×1.85–×2.30 the MDR-only baseline's at equal-or-better ¢/auth (73.4 vs 75.0 on the two stable scenarios).** So the spec's "+X pts auth gain" is wrong **as a signed claim** — the promised gain is a measured concession, redeemed on the margin axis: the honest pair is `(16.1…20.7 pts Δauth conceded, ×1.04…×2.30 margin returned)`. The document's committed sentence, carried in `BENCHMARKS.md` §B1 and here verbatim: *"auth rate waves sixteen to seventeen points of concession to the cost-only baseline to hold a margin multiple between 1.85 and 2.30 under matched effective cost per authorization, and the worst it got, versus the best static-router number on the same scenario, was over twenty points at ×1.07."* Margin rows carry MAE (4.25–4.29 pts) + arms-touched on every row (issue text), and the anchors `27,376.2 ¢/1k (70.49%)` (shipped TS, baseline-steady-v1@sha256:b49193b7e715, n=60,000, seed 20260916 — verbatim from spikes/0015-ope/RESULTS.md) and `14,787.7 ¢/1k` (MDR-only, same world) are hard gates at ±0.051 ¢/1k and ±0.005 pts.
2. **Decision-time latency sits inside ADR-0001’s 2 ms p99 wall and 20 µs p99 in-engine CPU budget as measured algorithm cost; the measured row is masked, the native projection is a labelled model, and the Go rows stay PENDING with the gate armed.** Method (decision, isolated from simulation): a full committed drive of the shipped Router on `baseline-steady-v1@sha256:b49193b7e715` (n=60,000; 10,000 under `--quick`), `time.perf_counter_ns()` bracketing `decide()` ONLY — constraint filter and score-EV sampling inside, posterior updates and world answers outside, exactly what production pays per decision. Latency quantiles are p50/p99/p99.9 (the latency-SLO set — R8's authored q50/q90/q99 governs margin/window quantiles, not SLO tails). Measured on this generated-date box (a noisy CI sandbox — these digits are host facts under R121): **p50 107.6 µs, p99 196.0 µs, p99.9 246.3 µs** (CPython 3.11, masked with `<!-- @timing -->`; the values are host facts, never digested or gated — issue text's "[no fabricated numbers: masked]" applied). The CPython reference on that noisy box already sits **10× inside the 2 ms p99 wall**. A **native-band projection** (labelled MODEL — the conservative 10×–30× range of ADR-0001 §1’s documented interpreter-dominated numeric-loop factors, not a measurement; the 100× end is not claimed) lands at **3.6–10.8 µs p50 / 6.5–19.6 µs p99**, still clearing the 20 µs p99 in-engine budget at the pessimistic 10× end (19.6 µs on the noisy box; the B1–B5 verdict gates never re-assert a host number — the clearance is the design judgment this bullet records, structural gates only per R121 — the budget is a property of the algorithm, not a hope about the compiler. Go reference rows are PENDING-ARMED: the repo contains no Go implementation today; the gate (`--go-bench`, must read ≤20 µs p99 in-engine / ≤2 ms p99 wall at 5,000 d/s on 4 vCPU) is committed so the day one exists the same script produces the row and flips the verdict. **CI rule: benchmark latency asserts the shape of the PENDING/PASS line and the model-band claim only, never the absolute µs — absolute numbers are mask-locked host facts under this ADR’s R121.**
3. **Z% is measured as `100·(oracle−shipped)/oracle` where oracle = the shipped score functional fed true rates at every timestep through the identical execution loop, boundary = margin ¢/1k at decision index vs the oracle's at the same index, horizon = full 60k plus post-warmup (first 10,000 dropped), and the clairvoyant upper-bound gap prices the score functional itself so a small Z cannot hide behind a weak oracle — anti-cherry-picking by construction.** Measured (full run, n=60,000): Z full/post-warmup = **2.99% / 3.13%** on baseline-steady-v1, **5.49% / 6.04%** on black-friday-degraded-v1, **3.05% / 3.20%** on outage-recovery-v1; shipped ≤ oracle ≤ clairvoyant ordering asserted per scenario; clairvoyant gaps **15.22% / 18.41% / 15.22%**. Report Z% next to its gap, never alone (the still-optimistic clairvoyant column is committed in the same table, not selected away for the README). The shipped rows are bit-identical to §B1's (one run serves both sections — regret is never spread across two different runs), and the oracle is a definition, not a fit: it receives exactly the information the ticket promised, true rates, through the same gate the shipped policy uses.
4. **OPE quality is measured exactly by the #17 text's certification procedure, certified as the ADR-0014 §4 gate with its replicate floor — and the ADR-0014 architecture choice directly settles the naive-IPS objection by measurement.** Section B4 of the script runs the five-step protocol: (V1) one content-addressed world serves both policies; (V2) run the logging policy P1 (shipped TS, `policy seed 20260916`) over 30,000 decisions of `baseline-steady-v1@sha256:b49193b7e715`; (V3) replay the `shift(target, ρ=0.2)` overlay through the SAME world instance for paired ground truth (estimates from P1's own decision log, so the pairing is exact, not sampled); (V4) certify `support ≥ 1,000 logged head(target) decisions` — decided before any estimator runs, else the query is REFUSED — and `|estimate−truth| ≤ max(1,500 ¢/1k, 75%|Δ|)` at N ≥ 30,000; (V5) re-run on three re-seeded worlds (+10k/+20k/+30k) and report the whole table — targets ('foxtrot','charlie'), 8 support-bearing queries. The certification floor ADR-0014 measured on its quadrature protocol (R111, mean −948.6/RMS 951.0 ¢/1k on the headline shift(foxtrot,0.2) across four 60k worlds, support-rich classes ≤160) is cited as context; **this benchmark's own restated floor over its 8 queries is mean −527.1 ¢/1k, RMS 811.1** — the spread ships in the file rather than behind a point estimate, and every gate row PASSes at the §4 bound. "±N% at 95% CI" resolves to this table: |err| is quoted against |Δ| on the same row (1,277.4 vs 1,645.6 on the headline query; 11.4–372.1 against 14.6–54.5 on the support-rich class), so the percentage exists only with its denominator attached. The unclipped-IPS catastrophe spike 0015 measured (+9.1M ¢/1k on one thin-propensity row) is why the shipped estimator is the clipped one — a property of the gate, not a toggle.
5. **Scenario catalogue: five named, versioned, content-hashed fixtures in `simulator/scenarios/examples/`, catalogued by `check.py --catalog`, hashed by canonical serialization, pinned in the script (hard FAIL on drift), and the determinism digest is a regression fixture.** The five on disk: `baseline-steady-v1@sha256:b49193b7e715`, `black-friday-degraded-v1@sha256:89c669ee7371`, `outage-recovery-v1@sha256:1e0cd5cd764e` (the three benchmark worlds), plus `idempotency-stress-v1@sha256:984db10a2af0` and `replay-trace-v1@sha256:abdba21ec1e9` (catalogued and pinned — measurement worlds in their own spikes even where no B1–B3 row exists). A content change is a new id plus a reviewable golden diff; catalogue drift = hard FAIL (asserted inside the script, not by convention in CI YAML). Determinism in depth: (i) the world digest (policy-free arm scan, n=20,000) is `sha256:0a60ead77355…`, identical across in-process re-runs; (ii) the **policy-state digest** — the shipped TS posterior arrays after 60,000 decisions, packed and hashed — is `sha256:0a09b7940e69…`, identical in-process ×2 AND in a fresh interpreter under the hostile case (`PYTHONHASHSEED=random`, `TZ=Asia/Kolkata`): the issue's "deterministic across runs" answered at the level that survives a re-install — hash seeds and timezones are the usual ways a run quietly becomes a different run, and neither may touch a benchmark file; (iii) one command with profile scaling (`--quick`/`--ci`/`--section`), zero side effects under non-full profiles (only the full profile writes `BENCHMARKS.md`); the behavioural digest of the run is the verdict table itself, which `--check` regenerates and diffs line-by-line except the explicitly-masked `<!-- @timing -->` lines (host timing, generation date).
6. **Anti-cherry-picking is structural, not editorial: four mechanisms are committed, and the worst-case runs and ships alongside the best.** (a) the pair-report convention — Δauth and ×margin on one line of one table, same scenario, same n, both ways (vs the cost-only endpoint AND vs the strongest static); (b) the static panel is **three named routers covering the degenerate cost-only endpoint AND both money-bearing routers**, all published per scenario — the reader sees the whole family and does not have to trust that the comparison policy was a fair one; (c) B3's clairvoyant column bounds the oracle's optimism in print, and B4's REFUSAL path answers the zero-support case instead of extrapolating confidently; (d) the verdict table hard-FAILs on anchor drift (the shipped and MDR-only anchors at ±0.051 ¢/1k / ±0.005 pts, the regret ordering, every replay-gate row, the floor restatement, catalogue drift) — the printed numbers are the gates (**24 PASS / 1 PENDING-armed / 0 FAIL** on the committed artifact). Worst-case reporting: the adverse extreme of every metric is in the file — black-friday's +20.66 pts / ×1.07 (the worst the pair ever got for the learned policy) sits next to baseline-steady's friendliest row; the 18.41% clairvoyant gap sits next to 15.22%. `--check` is the regression: the full profile re-runs and diffs every non-masked line of `BENCHMARKS.md`.

## Context

#17 is the design-repo's last measurement-integrity question before dependent README claims lock in. The issue text carries placeholders (`+X`, `≤Yµs`, `Z%`, `±N%`, 95% CI) that must resolve to concrete committed numbers — and an explicit instruction that what cannot be measured must say so, with the benchmark’s own host-masking convention (R121) stated here and nowhere presumed. The circumstances that shaped the six decisions:

- **The signed "+X" framing was testable and failed measurement** — under the ADR-0005 counter-coupling protocol, static routers authorize at ceiling because they never refuse; the learned policy spends those points on margin. The specifications in #17 assumed a specific sign; the simulations produced a different, richer fact that only survives as a pair.
- **ADR-0013 settled the measurement protocol** (run under identical world draws, report both metrics against baselines) — B1/B3 are literally `policy fn × world` simulations already, not a new rig. this ADR's own R121 settles what may not be printed (platform-masked rows), R9 settles what must be (MAE, arms-touched, refusal).
- **The committed [`spikes/0015-ope/RESULTS.md`](../../spikes/0015-ope/RESULTS.md) is the incumbent/expectation anchor**: the counterfactual hardware described in #17 already ran (spike 0015 on `baseline-steady-v1@sha256:b49193b7e715`, n=60,000, `policy seed 20260916`, with `27,376.2 ¢/1k, 70.49% auth` committed in its §O1) → those anchors are hard gates, not aspirations; this artifact's job is to close the #17 placeholder syntax with `BENCHMARKS.md` rows that consume ADR-0014 §4's floor.
- **The digest machinery is the dependence edge**: ADR-0013's counter digest + golden-file pins here make "deterministic across runs" an executable line in CI, not a documentation sentence.

## Consideration-by-consideration analysis

### 1. "Cost-only baseline" — the optimisation that collapses, and what to do about it
R25 specified "swept cost-only frontier" as an *axis*, but under `min Σ c̄(s)·1[ŵ(s) ≥ q]`, the feasible frontier collapses to the min-MDR point for every `q` in the q∈[0,1] range: lower-q adds more processors; higher-q refuses more; neither changes which processor minimizes cost among the safe. Three routers report the row instead of two, because the *shape* of the frontier is the finding: the MDR-only endpoint is what ADR-0003 rejected on this fleet; the loaded-cost router is what accounts payable would build; the EV-table is the margin-blind ris-approximant. All three are named, all three beat the learner on auth, only the MDR-only endpoint is equal-cost. Where the numbers land: see B1 table.

### 2. "+X relative to what, under what load" — the pair
#17's sign-vs-measurement conflict resolves by measuring the pair, not by picking a sign. Baseline for Δauth: `mdr_only` (the honest cost-only endpoint, not a strawman). Load: per-scenario TPS and 60k decisions under `policy seed 20260916` for TS, `expectations-*` seeds for statics. Concurrent conditions: `baseline-steady-v1`, `black-friday-degraded-v1`, `outage-recovery-v1`. The measured concession is a property of TS's refusal-driven routing (η floor + gate), not an accident of statics slacking; the margin multiple is the reason the concession exists.

### 3. Oracle regret — the boundary question asked in #17, resolved as decision
Policy-regret boundary set to decision index (per `ADR-0005`'s seed-oracle-construction: oracle arg-maxes true expectations given the *shipped play*'s world draws — hence "identical execution loop" in Decision 3; a different loop would measure a different estimand). warmup: 10,000 dropped decisions, reported post-warmup alongside full-horizon. The clairvoyant acknowledges the relevant epistemic limit: even an oracle can't beat shipping-the-future-draws, and the gap (14–19%) vs Z (2.5–6%) tells you where future regret work pays.

### 4. OPE ±N% at 95% CI
Solved by ADR-0014's design and certified by its §4 gate: the four-world floor *is* the CI's calibration. `±N%` reported as `|err| / |Δ|` with the |Δ| column printed adjacent — no percentage without its denominator. B4 reuses `spikes/0015-ope/ope.py` as a library (no re-implementation; the script imports the same code the ADR certified).

### 5. Scenario catalogue — why version pins are the whole mechanism
A "named benchmark scenario" has no meaning without the content hash: the name captures intent (`black-friday-degraded-v1`), the hash pins the world. Same-scenario-repeatability fails closed (`check.py` import + assertion inside the script, not by convention in CI YAML).

### 6. Anti-cherry-picking — structural vs editorial
Each editorial fix (a README sentence) decays; each structural fix (an assertion whose failure breaks `make benchmarks`) cannot be edited away silently. The four mechanisms in Decision 6 are the compile-time complement of the writing rules in the other ADRs (R30 labelling, R121 host-masking, R25 procedure): the script enforces what the prose commits.

## Payload for dependent tickets
- **README.md** — replace `+X`/`≤Y`/`Z%` placeholders with citations of `BENCHMARKS.md` rows (the tables themselves; the numbers in this ADR are the committed artifact's digest of them). The v1 static-baseline row stays as today (the statics comparison is B1, not a new section).
- **#16 dashboard work** — B5's policy-state digest is the provenance key to publish alongside any live panel numbers; the support diagnostics format `{head_rows, ess_frac, ew_bar}` is inherited from ADR-0014 as the panel's row footer.
- **Future spikes** — one new section name (`B6`, `B7`, …) and one CI row each; sections are addressable (`--section=B1,…`) precisely so a spike's measurement can land without rerunning the OPE gate.

## Consequences
**Positive**: one command regenerates the artifact and returns a machine-checkable verdict; the signed-claim inversion (Decision 1) cannot sneak back — the anchor row and the pair text are both gated; anchors make re-runs comparable across machines without sharing hardware (masked latency rows excepted, which now carry an explicit no-assert contract).

**Costs / accepted risks**: ~15-25 min full run wall time places the gate in pre-merge, not pre-commit ("does running this block CI?" — yes by design at merge; `--quick` is the dev loop, `--ci` the PR gate). The B1 anchor values freeze the spike-0015 run as the reference TS — any deliberate ADR-0006/0007 algorithm change must consciously re-anchor (that is the feature, but it makes algorithm PRs heavier). Go rows stay PENDING until a Go port exists; that is recorded, not hidden.

**Design rules established**
- **R118** "The cost-only baseline is R25's procedure closed, anchored at the minimum-MDR endpoint; equal effective cost is per authorized transaction; report statics as a named panel, never 'the static'."
- **R119** "Benchmark claims ship as measured pairs on the same row — Δauth with ×margin — with MAE and arms-touched attached to every margin number; no single-number headline survives alone."
- **R120** "`Z%` denominators are printed next to the numerator or not printed; oracle/clairvoyant ordering is asserted, not assumed."
- **R121** "Measurement latency rows assert verdict-shape and native-band models only; absolute µs are masked host facts (this rule — the host-masking convention), and CI compares masks, never absolute timings."
- **R122** "A scenario row exists only against a content-hash-pinned catalogue entry; regeneration is one command; any section/output change re-runs the whole gate."

## Reopen triggers
- `mdr_only` anchor drift > noise (deliberate algorithm change upstream or a deeper protocol bug); investigate as a report, never silently re-anchor.
- Post-warmup Z > 10% on any scenario (regret grew — the bandit is not converging as ADR-0007 predicts).
- Go reference implementation lands → flip PENDING-ARMED rows, audit the masked-shape comparison.
- OPE floor regeneration (ADR-0014 trigger 4) regenerates R111 at new values → re-commit §B4 and the floor in lockstep; B4's regression anchor is a **COPY**, not a view — it must never disagree with what §4 prints.
- Catalogue adds scenario ≠ measured → add a row in the same commit that adds the YAML.
- Any README or dashboard rewrite that drops the `BENCHMARKS.md` citation on a headline claim — the citation is contractual (R119).

## Alternatives considered
- **Report only the pair's margin component ("the honest win")**: conceals that auth concessions are the mechanism; #17's `worst-case` instruction and R119 forbid it.
- **Label the B1 statics "the cost-optimal static family" (ADR-0003's rejected commit)**: ADR-0003 already established no such committed family exists on this fleet; resurrecting the label as Benchmark's shorthand would re-litigate a closed adversarial question with measurement, outside its original context.
- **Blend the EV-table with MDR-cost into one *"q*×weighted" super-static**: tried under every plausible normalization; none reconstructs well-formed routing behaviour under the counter-coupling protocol, and all variants lose verifiability ("which router produced this row?"). Named routers beat tuned routers.
- **Synthetic strawmen worse than min-MDR (`random_router`, `first_fit`)**: the panel already contains the strongest legitimate statics; adding weak entries to stretch the ×margin axis is exactly the cherry-picking this ADR exists to prevent — refuse to create rooms for bad-faith comparison.
- **Wall-clock latency numbers as CI gates**: rejected by R121: host facts belong in print, not in assertions; the gate asserts the shape (PENDING-ARMED vs PASS) and the native-band model, never the µs.
